## ข้อสรุปและฐานก่อนแก้ในรอบนี้

ฉบับที่รับมาตรวจมีเนื้อหาลึกและเครื่องมือพร้อมอยู่แล้ว จุดที่ audit พบและใช้ปรับรอบนี้คือ **ลำดับการอธิบายให้เริ่มจาก “ใส่ตรงรุ่น ทำไมยังไม่ถูกใจ” ก่อนพาไปเลือกจำนวน Way** ไม่ใช่เขียนใหม่ราวกับไม่มีข้อมูลเดิมหรือเพิ่มความยาวเพื่อให้ดูเหนือกว่า

ในฐานก่อนแก้ บทนำกล่าวถึงรถเด้ง/กระด้างแล้ว แต่กล่องคำตอบสั้นสรุป 1/2/3-Way ทันที ทางลัดแรกพาไปภาพช่องปรับ และพื้นฐาน spring/damper อยู่ภายหลังภาพช่องปรับ ส่วน fitment อยู่ลำดับท้าย ผู้อ่านจึงอาจเริ่มคิดว่า “ต้องเพิ่ม Way” ก่อนเข้าใจว่าตนต้องการแก้อะไร ข้อสังเกตนี้เป็น editorial inference จากลำดับเนื้อหา ไม่ใช่ผล usability test หรือข้อมูลพฤติกรรมผู้ใช้

## วิธีใช้ Skyscraper กับงานนี้

ใช้กรอบ **Search → Gap → Verify → Improve → Add firsthand value** ตาม [บทสนทนา Skyscraper Technique Content Creation ที่ผู้ใช้อ้างอิง](chatgpt-conversation://6aae075d-e9e0-83ec-a464-d71bc43a11cd) และบันทึก audit ก่อนหน้าในโครงการ โดยแยกสิ่งที่ตรวจเองในรอบนี้ออกจากบริบทที่รับมา:

1. **Search:** ค้นและอ่านหน้า benchmark ภาษาไทย/อังกฤษตามเจตนาการซื้อและตั้งช่วงล่าง ไม่เรียกรายการนี้ว่า Top Google Thailand
2. **Gap:** เทียบความสามารถในการพาคนอ่านจากอาการไปสู่การตัดสินใจ ไม่ใช้จำนวนคำเป็นตัวตัดสิน
3. **Verify:** ใช้หน้าและคู่มือผู้ผลิตควบคุมข้อเท็จจริงทางเทคนิคของแต่ละรุ่น; หน้าสื่อใช้เพื่อ audit การสื่อสาร ไม่ใช้รับรองกลไกแทนผู้ผลิต
4. **Improve:** ย้ายคำตอบเรื่องความเหมาะสมและพื้นฐานขึ้นก่อน แล้วให้รายละเอียดเดิมตอบคำถามที่เกิดตามมา
5. **Add firsthand value:** เพิ่ม buying brief และตัวอย่างคิดที่ผู้อ่านใช้กับรถตัวเองได้ แต่เรียกให้ถูกว่าเครื่องมือ/ตัวอย่างต้นฉบับ **ไม่ใช่ firsthand road-test evidence**

## ช่องว่างสำคัญและการปรับที่เสนอ

| สิ่งที่ต้องให้ผู้อ่านเข้าใจ | รูปแบบที่แนะนำ | หลักฐาน/ขอบเขต |
|---|---|---|
| **Fitment กับ suitability ต่างกัน** | เปิดด้วย “ใช้กับรถนี้ได้” กับ “ตอบโจทย์เจ้าของคนนี้ไหม” พร้อมเป้าหมายความสบาย/การควบคุม/ความสูง | Fitment ตรวจปี รุ่นย่อย ตลาด ระบบเดิม น้ำหนักเพลา และ part number; ความเหมาะสมต้องมีบริบทใช้งาน ไม่ให้คะแนนแบรนด์จากชื่อ |
| **Spring, damper และ travel ทำงานร่วมกัน** | ย้ายพื้นฐานขึ้นก่อน Ways และอธิบาย bump/droop กับ bump stop ให้เห็นเหตุผล | ปุ่มแรงหน่วงไม่เปลี่ยน spring rate และไม่สร้างระยะทำงานเพิ่มโดยอัตโนมัติ; รายละเอียด preload/ความสูงขึ้นกับโครงสร้างและคู่มือ |
| **รถรุ่นเดียวกัน คนละโจทย์** | ตัวอย่างสมมติเจ้าของสองคน: ครอบครัว/สัมภาระ/รอยต่อ กับคนเดียว/ถนนเรียบ/สนามบางครั้ง | ไม่กำหนดผู้ชนะหรือค่าคลิกจากสถานการณ์ และไม่อ้างว่าเป็นเคสลูกค้าหรือผลทดสอบจริง |
| **Buying brief ก่อนถามว่าแบรนด์ไหนดี** | แบบกรอกอาการหลัก สิ่งที่ยอมเสียไม่ได้ ถนน ยาง โหลด ความสูง และงบรวมบริการ อยู่ในบทความและต่อกับ checklist เดิม | ระบุ “ต้องยืนยัน” เมื่อไม่มีหลักฐาน fitment ราคา สต็อก หรือรับประกันไทย |
| **Spring rate ไม่เท่ากับ wheel rate** | worked example สั้นก่อน deep dive ที่ซับซ้อนกว่า | นิยาม motion ratio ให้ชัดก่อนสูตร; หากใช้ `r = ระยะสปริง / ระยะล้อ` ตัวอย่างอุดมคติ `k_w ≈ k_s r²` ต้องระบุสมมติฐานและตรวจแหล่งเทคนิคก่อนลงบทความ ตัวเลขสมมติไม่ใช่สเปก EV รุ่นใด |
| **ข้อมูลที่ทำให้ร้านแก้ปัญหาได้** | เชื่อม symptom triage → ตรวจทางกล/ระยะ → baseline → setup log ที่มีอยู่ | ไม่ฟันธงสาเหตุจากคำว่า “แข็ง” อย่างเดียว ไม่ให้สูตรคลิกข้ามรถ ไม่ใช้การขับถึงขีดจำกัดบนถนนสาธารณะ |

ลำดับแนะนำ: ปัญหาที่เจอ → fitment/suitability → spring/damper/travel → รถเหมือนกันแต่โจทย์ต่างกัน → buying brief → โครงสร้าง/ช่องปรับเดิม → wheel-rate และ deep dive → ตัวอย่างแบรนด์พร้อมภาพผู้ผลิตและลิงก์ต้นทาง → triage/baseline/log → อ่านต่อเรื่องยางและศูนย์ล้อ

เพิ่ม FAQ ที่ตรง intent เช่น “เพื่อนใช้รุ่นเดียวกันแล้วดี ทำไมรถฉันไม่เหมือนกัน” และ “อ่อนสุดแล้วยังกระด้าง ต้องเปลี่ยนโช้คเลยไหม” โดยคงข้อยกเว้นและจุดหยุดตรวจรถ ตัวชี้วัดความสำเร็จของเนื้อหาคือผู้อ่านระบุโจทย์และสิ่งที่ต้องยืนยันได้ ไม่ใช่จำนวนคำหรือจำนวนแบรนด์

## สถานะหลังแก้ที่ยืนยันจาก source

ตรวจไฟล์จริงซ้ำหลังผู้แก้เนื้อหาแจ้งพร้อมแล้ว พบสารบัญ **21 หมวด**, การเปรียบเทียบ **9 รายการ**, FAQ **10 ข้อ**, ภาพประกอบผ่าน `DamperPhoto` **8 ภาพ**, explorer และสถานการณ์เดิมยังอยู่ การมีเนื้อหาใน source ยังไม่แทนผล browser QA หรือ deployment

| งานที่เสนอ | หลักฐานที่มีใน source หลังแก้ |
|---|---|
| เปิดด้วยปัญหาเจ้าของรถ | `src/lib/damper-article.ts` เปลี่ยน subtitle/description/cardDescription ให้พูดเรื่องตรงรุ่นกับเหมาะกับเรา; กล่องคำตอบสั้นและทางลัดแรกเริ่มที่อาการ/ข้อจำกัด |
| Fitment แยกจาก suitability และผู้ใช้ต่างกัน | `#fitment-before-brand` มีสองด่านและตัวอย่างเจ้าของรถรุ่นเดียวกันสองคน พร้อมระบุว่าเป็นตัวอย่างสมมติ ไม่ใช่ผลทดลอง |
| พื้นฐานมาก่อน Ways | ลำดับจริงและสารบัญเริ่ม `#fitment-before-brand → #basics → #types → #spring-height → #explorer`; ครอบคลุมยาง spring damper bump stop preload และ bump/droop |
| Worked wheel-rate example | `#wheel-rate-example` เป็น native details ปิดเริ่มต้นให้มือใหม่อ่าน preload/travel ก่อน และเปิดอ่านลึกได้โดยไม่ใช้ JavaScript; นิยาม MR เป็นระยะสปริงหารระยะล้อ รวมผลมุมแล้ว ใช้ `100 × 1.0² = 100` และ `100 × 0.7² = 49 N/mm`; ระบุ linear spring, ratio คงที่ใกล้ ride height, ส่วนที่ไม่รวม และลิงก์ [Eibach worksheet](https://eibach.com/storage/catalogs/suspension-worksheet.pdf) |
| Buying brief ที่ใช้ต่อได้ | `#buying-brief` อยู่หลัง baseline ก่อน toolkit มีอาการ ผู้โดยสาร เงื่อนไขที่ยอมเสียไม่ได้ งบรวม งานติดตั้ง และลิงก์ download; checklist เดิมยัง 12 ข้อ เพิ่มเหตุการณ์/งบ/เกณฑ์ประเมินและการตรวจบูช |
| รักษาความลึกและภาพจริง | เก็บ 9 รายการเปรียบเทียบและ deep dive เดิม; ภาพ Öhlins เปลี่ยนเป็น TES MA10S1 จากหน้าผู้ผลิต Tesla Model 3 ปี 2020 พร้อมข้อจำกัด fitment |

อัปเดต `scripts/verify-coilover-article.mjs` ให้ตรวจ reading order/TOC, คำตอบ pain point, บริบทสมมติ, นิยาม/ผล/ข้อจำกัดของ wheel-rate example, buying brief และ download, source link ของภาพ รวมทั้ง metadata consistency คง regression 4 viewport, ขยายข้อความ 200%, no-JavaScript, 9 comparison rows, 4 explorer modes, 3 scenarios และแบบพิมพ์เดิม สคริปต์ไม่รับรองความถูกต้องจากจำนวนคำและไม่ใช้ผลผ่านแทนการอ่านภาพจริง

การตรวจ syntax และ ESLint ของสคริปต์เป็น gate ขั้นต้นเท่านั้น ส่วน production build, การรัน browser suite ต่อ server ที่สร้างจาก source นี้, ภาพหน้าจอ และการตรวจโดเมนจริงต้องมีหลักฐานผลรันแยกก่อนอ้างว่าเผยแพร่สำเร็จ

## สถานะข้อมูลและข้อห้ามอ้างผลเกินหลักฐาน

- Google Thailand ranking, search volume, backlinks/referring domains, traffic และ conversion ของ benchmark: **Data unavailable** ไม่มีการอ้างว่าเป็นหน้าชนะ SEO หรือรับประกันอันดับหลังแก้
- Firsthand road-test, damper dyno, ระยะเบรก, lap time หรือคะแนนความสบายที่ควบคุมตัวแปรของ EVSELECT: **Data unavailable** ไม่สร้างเคสลูกค้า นักทดสอบ คุณวุฒิ หรือผลวัดขึ้นมา
- Original scenarios, buying brief และ setup log เป็นคุณค่าที่สร้างเพิ่ม แต่ไม่เท่ากับประสบการณ์ทดสอบสินค้าโดยตรง
- ไม่ได้ทำ outreach และไม่มี authorization สำหรับการส่ง outreach ในงานย่อยนี้; ไม่ได้ซื้อบริการหรือสั่งสินค้า
- เอกสารนี้เป็น audit/evidence note ไม่ใช่หลักฐานว่า implementation, browser QA หรือ deployment รอบใหม่เสร็จแล้ว ต้องตรวจแยกจาก source และผลการทดสอบจริง
- ทุก performance claim ต้องตรงกับแหล่งและบริบท ไม่ใช้ภาพสวย ชื่อแบรนด์ จำนวน Way หรือราคาเป็นหลักฐานว่าเหมาะที่สุด ไม่มีการเติมราคาหรือสเปกที่ตรวจสอบไม่ได้
